Cliente

Primer flujo de uso

La API se organiza por recursos. La app consumidora conserva el tenant, el token y la logica de negocio. 

import { NextivaClient } from "@nextiq/nextiva-sdk";

const nextiva = new NextivaClient({
  domain: "tenant.thrio.io",
  token: process.env.NEXTIVA_TOKEN,
  authorizationMode: "raw"
});

const session = await nextiva.users.session.get();
const contacts = await nextiva.data.contacts.list({ query: { pageSize: 10 } });
const answer = await nextiva.ai.predict({
  message: "What should the agent answer next?",
  kb_ids: ["knowledge-base-id"],
  workitem_id: "workitem-id"
});

Limites

Que no entra en este SDK

No se mezclan wrappers de `webs`. Rutas locales como /api/workitem, /api/wieland/*, /api/pulseforms/* y /api/ncc-builder/* siguen siendo responsabilidad de la aplicacion. Sugar, HubSpot y proveedores LLM tambien quedan fuera.
